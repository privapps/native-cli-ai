# nca Documentation

This is the documentation hub for nca. The directory names describe the audience and lifecycle of each document.

## Start here

- [User Guide](user/index.md) — installation, commands, configuration, providers, tools, sessions, permissions, and skills.
- [Product](product/index.md) — product scope and the current actionable roadmap.
- [Reference](reference/index.md) — architecture, crate responsibilities, technology choices, orchestration, context management, and terminal guidance.
- [Design](design/index.md) — active and historical implementation plans and specifications.
- [Research](research/index.md) — investigations, benchmarks, and research notes.

## Documentation rules

- User-facing behavior belongs in `user/`.
- Product scope and roadmap decisions belong in `product/`.
- Stable technical facts belong in `reference/`.
- Plans and specifications belong in `design/`; active work is separated from archived or superseded work when lifecycle folders are introduced.
- Research notes belong in `research/` and should not be treated as implementation authority without an associated plan or specification.
- Plans and specifications should include type, status, date, related documents, and last verification date.

The root README remains the quick-start surface. Use this hub when you need the complete documentation map.
